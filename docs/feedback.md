## Feedback from mentor

### Week 2

The mentor emphasized that the primary priority should be setting up and stabilizing the development environment before expanding features, which shifted the focus away from broad functionality toward building a solid foundation. Due to these environment-related constraints, the project scope was intentionally reduced to avoid generalizing across multiple datasets or schemas, instead concentrating on a single, well-defined HR schema. This is excpected to expand as we learn. As a result, a key technical decision was made to standardize on Python as the core language for development, ensuring shared familiarity, and smoother collaboration.

### Week 3

Mentor explains that before building new features, we should make sure the development environment is reliable, consistent, and easy to reproduce. A stable environment ensures that the project runs the same on every machine, dependencies are correctly installed, configuration like API keys and environment variables are organized, and tools such as linters, formatters, and Git settings do not cause unnecessary issues. When this foundation is solid, we avoid spending time debugging setup problems, version conflicts, or “works on my machine” type of errors, which can slow development much more than delaying features at the beginning.

### Week 4

Mentor is emphasizing an incremental approach to progress, where large goals are achieved by consistently solving small, manageable problems one at a time. Instead of trying to tackle an entire feature or system all at once, the idea is to break the work into clear, focused tasks—such as fixing a bug, implementing a single function, improving one part of the setup, or validating a small piece of logic and fully completing each step before moving on. This method allows us to detect issues early, adjust plans as needed, and maintain clarity about what has been completed versus what remains. 

### Week 5

Same advise as week 4, keep working on minor problems, one at a time, until a major goal has been achieved, and repeat this process for all the projected goals of the team. When starting the implementations of the new orchestration tools, make sure to make robust test along the way so bugs don't accumulate until the end and make the code confusing to work with and time-consuming.

### Week 6

Mentor introduced the Claude code extension from Anthropic as a tool to help structure decision-making steps within the orchestration process, and encouraged us to focus on building a solution that is practical and good enough to deliver. The emphasis was on using the tool to organize logic clearly while prioritizing progress toward a presentable, working outcome rather than pursuing perfection.

### Week 7

The mentor recommended using TypeScript for the figure orchestration tools instead of R because it is more suited for structured coding and offers a better learning experience for the team. He also suggested researching similar projects to gather ideas and inspiration, then building on those insights to create something original that goes beyond what already exists.
